# 阶段 7：联合调试、性能统计与验收

## 1. 当前完成范围

阶段 7 已完成无需开发板即可验证的代码和验收工具：

- 启动顺序保持为摄像头/显示、RGB VDMA、灰度 VDMA 与中断、CNN、OSD；所有初始化失败均打印错误并退出。
- 增加直通、识别、OSD 固定框诊断三种运行模式。
- 增加运行期采集率、ROI 复制率、识别处理率和错误统计。
- 增加预处理平均耗时、CNN 平均/P95/最小/最大耗时；P95 使用最近 256 次成功推理的精确排序结果。
- 输出应用静态内存、CNN 工作区和两个 DDR 三缓冲环的大小。
- 建立实拍样本、冷启动和耐久测试记录表，以及混淆矩阵和性能报告工具。

阶段 7 没有修改 PL，复用阶段 6 已通过时序的 bitstream/XSA；本阶段更新 PS 应用和启动镜像。

## 2. 串口命令

| 命令 | 功能 |
|---|---|
| `a` | 直通模式：关闭 OSD，并停止预处理与推理 |
| `c` | 识别模式：启用预处理、CNN 和 OSD |
| `d` | OSD 诊断：显示固定框、数字 8 和 99% |
| `0` / `1` | 关闭/开启 PL 灰度均值滤波，下一帧生效 |
| `o` | 保持当前模式并切换 OSD enable |
| `p` | 打印最新 28×28 二值模型输入 |
| `g` | 打印同一次识别的模型输入和 10 类分数 |
| `v` | 打印最新 10 类分数 |
| `s` | 打印帧率、VDMA、性能、结果和内存统计 |
| `r` | 重置性能统计窗口和帧率计时基准 |
| `h` | 打印命令帮助 |

`PERF` 中的时间只包含 ARM 预处理和 CNN 计算。它不等于摄像头到 LCD 的端到端延迟。
端到端延迟必须通过画面切换与显示同步拍摄等方法测量，并填入现场测试表。

## 4. 实拍准确率测试

记录文件：[field_test.csv](../tests/field_test.csv)。每个数字至少采集 30 张此前未用于调参的图片，
总计至少 300 张。测试集应覆盖普通室内光、偏暗、细/中/粗笔画、轻微倾斜、不同距离和阴影背景。

- 若预处理没有找到候选，填 `localization_status=not_found`，prediction 和 confidence 留空。
- 若找到候选，填 `localization_status=found`、预测 0–9 和 0–1 置信度。
- `end_to_end_ms` 只能填外部实测结果，可以留空，不能填写单次 CNN 耗时代替。

生成指标：

```powershell
& tests/.venv/Scripts/python.exe tests/analyze_field_test.py tests/field_test.csv `
    --output tests/results/field_test_report.json --require-complete
```

报告输出定位成功率、总体准确率、找到数字后的分类准确率、各类召回率、包含 `not_found`
列的混淆矩阵，以及端到端平均/P95。建议验收目标为总体准确率不低于 90%，最终结论以实拍报告为准。

## 5. 性能和稳定性测试

1. 烧写 [BOOT.BIN](../artifacts/stage7/BOOT.BIN)，启动后按 `c`，再按 `r` 清零统计。
2. 依次展示测试集；每隔一段时间按 `s`，将串口完整保存为文本。
3. 解析串口日志：

   ```powershell
   & tests/.venv/Scripts/python.exe tests/analyze_uart_log.py board_uart.log `
       --output tests/results/board_runtime.json
   ```

4. 识别处理率目标先设为 ≥5 次/秒；检查 VDMA errors 和 inference errors 为 0，丢帧没有持续增长。
5. 用 [cold_boot_test.csv](../tests/cold_boot_test.csv) 记录 10 次完全断电冷启动。
6. 用 [endurance_test.csv](../tests/endurance_test.csv) 记录至少 2 小时连续运行；期间不得死机、重启、持续增长错误或显示撕裂。
7. 分别用 `a`、`c`、`d` 检查原图直通、正常识别和 OSD 定位；快速换纸检查帧首统一更新。
8. 录制上电、0–9 识别、无数字、模式切换和统计输出的完整演示视频。
