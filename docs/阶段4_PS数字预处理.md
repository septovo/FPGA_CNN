# 阶段 4：PS 数字预处理与候选提取

## 实现

`vitis/dual_ov5640_lcd/src/digit_preprocess.c/.h` 输入阶段 3 复制出的单通道灰度 ROI（最大 256×256，支持行 stride），输出原始摄像头坐标下的候选框和模型使用的 `uint8[28][28]`。处理顺序为：256 级直方图与 Otsu 反相二值化 → 5×5 矩形核闭运算 → 8 连通域 → 边界、尺寸、前景面积筛选 → 按上游仓库规则补黑边 → 面积缩放。工作缓冲由调用方提供，不在帧处理中动态分配内存。

本版本每帧只选择一个候选：前景像素数最多者；并列时选更靠上、再靠左的框。外边界 40 像素内、宽或高小于 14、超过 ROI 一半或前景少于 32 像素的区域被丢弃；连通域超过 1024 个时返回“噪声过多”。空白画面返回“无数字”。这与上游遍历所有外轮廓的行为不同，符合当前单数字首版范围。输出框的 `x/y` 已加上中心 ROI 在全帧中的偏移。

`main.c` 默认关闭 PL 均值滤波，以保持与原模型的灰度输入更接近；仍可用串口 `1` 开启、`0` 关闭。每复制 5 个稳定 ROI 处理一次，分阶段记录 Otsu、闭运算、候选筛选和缩放耗时。串口 `s` 输出累计统计；`p` 输出最近一次有效候选的 784 字节十六进制模型输入。此阶段仅准备输入，CNN 推理在阶段 5 接入。

## PC 对照测试

运行 `tests/build_preprocess_host.ps1`：用 Vivado 2020.2 附带的 MinGW GCC 构建同一份 C 代码，再用 `tests/.venv` 的 OpenCV 和固定模型执行 `tests/test_digit_preprocess.py`。运行 `tests/build_stage4.ps1` 可用 Vitis 2020.2 ARM GCC 完整编译链接应用。

| 检查 | 结果 |
| --- | --- |
| 46 张固定合成 ROI | PASS，包含 0–9、细/粗笔画、倾斜、阴影、边界、最小 14×14、空白与噪声。Otsu 阈值、二值图、5×5 闭运算图及候选框与 OpenCV 对齐；常规样本的 28×28 输入完全一致。 |
| 最小尺寸候选 | 28×28 输入有 8 个字节各差 1 灰阶，来自 `INTER_AREA` 边界处的取整；其余字节一致。 |
| 阶段 1 的 10 个固定纸面数字 | 10 个候选框均对齐；9 个输入逐字节一致，`test_003` 有 2 个字节各差 1。固定 TFLite 模型两版均预测为 **7**，置信度分别为 C 输入 **0.9997395873**、PC 黄金输入 **0.9997382760**。 |
| 空白、无效 ROI、密集噪声 | PASS；分别返回“无数字”、“参数错误”和“噪声过多”，不越界或无界搜索。 |
| ARM 应用完整编译链接和 Bootgen | PASS；无应用源码编译警告。ELF `_end` 低于视频缓冲起点 `0x01000000`。 |

纸面数字黄金对比通过把阶段 1 已闭运算的单个候选区域放入白底 256×256 ROI 来隔离验证后续框选、补边和缩放；46 张固定合成 ROI 则运行 Otsu 到缩放的完整处理链。该方法没有模拟真实摄像头噪声和 PL 灰度近似误差。
